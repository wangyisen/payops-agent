# mock-pay

A mock payments platform: the system PayOps Agent investigates. It serves a deterministic synthetic world (merchants, quotes, payouts with a full state machine, webhook deliveries, a banking partner's view, statement lines) on a frozen clock, so every investigation and eval run is reproducible.

```bash
make mock-pay   # http://127.0.0.1:8001/docs
curl -H "Authorization: Bearer dev-mock-pay-key" http://127.0.0.1:8001/v1/transfers?status=failed
```

## What makes it more than fixtures

- **Retry policy, enforced server-side.** `POST /v1/transfers/{id}/retry` re-runs nine checks before executing. Double-payout checks come first: the transfer failed, for a retryable reason, below the attempt limit; a timeout has had 30 minutes to settle; the partner's status is known and shows no payment for *every* reference the transfer was ever submitted with (a partner can execute an earlier attempt late); no statement shows a debit. Then the commercial checks: the quote is still valid and the merchant can fund the payout again. If the partner's status API is down, the retry is refused (fail closed). `GET .../retry-eligibility` is the same policy as a read-only dry run.
- **Idempotency keys.** Action endpoints require `Idempotency-Key`. A replay returns the stored response with `Idempotent-Replayed: true` and does not execute again; the same key with a different body is rejected; refused requests do not consume the key.
- **Planted scenarios.** Fourteen investigation scenarios (compliance hold, timeout-but-paid, partner outage, prompt injection in a webhook response, duplicate submission, ...) are described in [`docs/plans/00-mock-pay.md`](../../docs/plans/00-mock-pay.md). Their ground truth is written to [`evals/scenarios.json`](../../evals/scenarios.json), outside this package, so the API can never serve it.
- **Untrusted content.** Webhook response bodies, deposit references and names are controlled by outside parties. One merchant's endpoint returns a prompt-injection payload on purpose.

## Data

`src/mock_pay/data/*.json` is generated by `make seed` from [`seed/`](src/mock_pay/seed/) with a fixed seed and clock (`2026-03-11T09:30:00Z`). IDs are hashed from stable keys, so editing one part of the generator does not renumber everything else. A test fails if the committed files and the generator drift apart. The data has to survive someone following the money: balances traced back from today never go negative, merchants waiting for funds really were short, and an account the data calls closed or invalid is never paid again.

## Layout

| Module | Role |
|--------|------|
| `models.py` | Pydantic domain models (money is `Decimal`) |
| `domain.py` | State machine and retry policy: pure functions |
| `ledger.py` | How payouts, refunds, returns and deposits move a merchant's balance |
| `idempotency.py` | Idempotency-key store |
| `store.py` | In-memory state loaded from the seed files; actions run under a lock |
| `api.py`, `errors.py`, `app.py` | FastAPI routes, one error shape, app factory |
| `seed/` | Deterministic data generator and scenario definitions |
