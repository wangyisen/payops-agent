# 学习路线总览

这份文档是整个项目的学习地图：每个里程碑学什么、做出什么、怎么验收、面试会怎么问。每个里程碑做完后，会有一篇单独的学习笔记 `docs/learn/NN-*.md`。

## 1. 目标

这个项目同时要做到两件事：

1. **系统地学会 AI Agent 开发**：从“调一次大模型 API”开始，一路做到“带人工审批、能评测、能观测、能部署的 Agent 服务”。
2. **留下一个经得起追问的公开作品**：每一行代码都要讲得清为什么这样写，换一种写法会怎样。

和大多数 Agent 演示项目的区别在于：**把支付系统的工程习惯用到 Agent 上**，包括幂等、防重复打款、fail-closed、对账和纵深防御。一般的演示项目只关心“答得对不对”，这个项目还要回答“动钱的时候怎么保证不出事”。

## 2. 每个里程碑的学习节奏

1. **读计划**（`docs/plans/NN-*.md`）：要解决什么问题，怎么拆，怎么验收。
2. **先读测试，再读代码**：测试就是需求说明书。
3. **跑演示**：每个里程碑都有一条能演示的命令。
4. **读学习笔记**（`docs/learn/NN-*.md`）：概念、关键代码位置、面试常问。
5. **做练习**：每篇笔记末尾有 1–2 个要你亲手改代码的小练习。
6. **讲出来**：不看资料，用自己的话把 3–5 个核心概念讲清楚。讲清楚了，再进入下一个里程碑。

## 4. 各里程碑详细

### M0 · Mock 支付 API（地基）

**为什么要做**：Agent 需要一个“被排查的系统”。真实支付系统不能用，所以自己造一个：有转账状态机、报价、虚拟账户和入金、Webhook 投递记录、银行合作方视角、对账记录。数据全部是合成的，并且用**固定时钟**，保证每次排查、每次评测的结果都能复现。

**学习要点**

- 转账状态机：哪些状态之间能转换，为什么失败的转账不能随便重试。
- “超时后重试”为什么危险：我方超时，不代表合作方没付款。
- 幂等键：同一个 key 重放时返回同一个结果；同一个 key 配不同的请求，直接拒绝。
- Fail-closed：确认不了是否安全，就不执行。
- 纵深防御：服务端自己再校验一遍规则，不能只靠 Agent 守住。
- 标注和数据分离：场景的标准答案放在 `evals/`，API 永远不会把它返回给 Agent。

**验收**：`make check` 全部通过；每个排查场景都能通过 API 查到证据；对“已被合作方付款”的转账发起重试，服务端会拒绝。

**面试常问**

- 为什么 mock 系统要用固定时钟？
- 幂等键存什么？同一个 key、不同的请求体怎么处理？并发的两个相同请求怎么办？
- 怎么判断一笔失败的出款能不能重试？
- Agent 已经判断过了，为什么服务端还要再校验？

### M1 · 大模型 API 基础

**学习要点**

- 消息角色（system / user / assistant）、token、上下文窗口、`temperature` 等采样参数。
- 提示词结构：角色、任务、约束、输出格式、示例。提示词也是代码，要有版本、要测试。
- 结构化输出的几种做法：JSON 模式、JSON Schema 严格模式、用 tool calling 强制输出、提示词 + 校验 + 重试。各自的可靠性和限制。
- 流式输出：SSE、增量拼接、首 token 延迟（TTFT）怎么测。
- 错误处理：哪些错误该重试（429、5xx、超时），哪些不该（400、401、402），以及指数退避。
- 成本：输入 / 输出 token 单价、缓存命中，怎么算一次调用花了多少钱。
- 适配层：同时支持 OpenAI 兼容协议和 Anthropic 协议，上层代码不感知具体厂商。

**验收**：`payops triage` 把一段工单文本解析成经过校验的结构化结果；`payops explain <transfer_id> --stream` 流式解释一笔转账的状态，并打印 TTFT、token 数和成本；两种协议都能跑通；适配层有不依赖网络的单元测试。

**面试常问**

- JSON 模式和 JSON Schema 严格模式有什么区别？模型不支持严格模式时，怎么保证输出结构？
- 流式输出怎么实现？TTFT 怎么测，为什么重要？
- 哪些错误该重试？重试会不会带来重复副作用？
- 为什么要自己写适配层，而不是直接用某家的 SDK 或 LangChain？

### M2 · Tool calling：手写 agent 循环

**学习要点**：function calling 的完整往返（模型发起调用 → 执行工具 → 把结果回传 → 模型继续）；agent 和 workflow 的区别；最大步数和其他终止条件；工具出错时把错误作为工具结果回传，让模型自己调整；并行工具调用；上下文变长以后怎么处理。

**验收**：问“这笔出金为什么卡住了”，agent 能自己决定查哪些接口，给出带证据的结论；超过最大步数会安全停止；工具报错不会让程序崩溃。

**面试常问**：agent 和 workflow 有什么区别，什么时候不该用 agent？怎么防止死循环？工具报错怎么处理？

### M3 · RAG：检索 runbook

**学习要点**：文档切分策略（按标题、按长度、重叠）；embedding 和向量检索（pgvector）；关键词检索（BM25）；用 RRF 融合两路结果；重排序；回答必须带引用；检索质量评测（recall@k、MRR）。

**验收**：回答能引用 runbook 的具体小节；有检索评测脚本，能对比“只用向量”和“混合检索”的效果。

**面试常问**：为什么要混合检索？RRF 怎么计算？chunk 大小怎么定？怎么减少幻觉？

### M4 · LangGraph：用状态图重写

**学习要点**：state、node、edge、reducer；条件边；checkpoint 解决什么问题；`thread_id` 和多轮记忆；和手写循环相比，得到了什么、失去了什么。

**验收**：功能和 M2 一致，并支持多轮追问；进程重启后能从 checkpoint 恢复对话；有一篇手写版和 LangGraph 版的对比笔记。

**面试常问**：checkpoint 存了什么？为什么需要 reducer？什么时候不需要用框架？

### M5 · MCP：把支付工具做成标准服务

**学习要点**：MCP 的 tools / resources / prompts；stdio 和 Streamable HTTP 两种传输方式；用 zod 校验参数；客户端和服务端的能力协商；MCP Server 的安全风险（过度授权、工具描述投毒）。

**验收**：TypeScript MCP Server 同时支持两种传输方式；Python agent 通过 MCP 客户端调用工具；能在 Claude Desktop 或 Cursor 里接入演示。

**面试常问**：MCP 和 function calling 是什么关系？stdio 和 HTTP 怎么选？MCP Server 怎么做权限控制？

### M6 · 安全与人工审批

**学习要点**：动钱操作分两阶段（先返回“待确认动作”，审批后才执行）；确定性幂等键，保证一次审批最多执行一次；LangGraph 的 interrupt / resume；间接提示词注入（藏在工具返回内容里的指令）；为什么不能相信模型给出的 ID，要校验当前操作员的权限范围。

**验收**：重试出款必须审批后才执行；重复提交同一个审批只会执行一次；种子数据里埋好的注入指令被识别并忽略；越权查询其他商户的转账会被拒绝。每一条都有测试。

**面试常问**：怎么保证审批过的动作只执行一次？审批等待期间进程重启怎么办？间接提示词注入是什么，怎么防？

### M7 · 评测与可观测

**学习要点**：构建 50–100 条标注用例；确定性检查（该调的工具调了没有、有没有越权动作、引用对不对）加 LLM-as-judge（结论是否正确、是否有依据）；和基线对比；在 CI 里跑回归；tracing（Langfuse 或 OpenTelemetry）；准确率、TTFT、P95 延迟、单任务 token 成本。

**验收**：一条命令跑完整个评测并输出报告；CI 里跑一个小规模的回归子集；README 里有指标表。

**面试常问**：没有标准答案的问题怎么评测？LLM-as-judge 有哪些偏差，怎么校准？怎么在 CI 里控制评测的成本和结果波动？

### M8 · 产品化

**学习要点**：FastAPI + SSE 推送 agent 的中间过程；Next.js 控制台（对话、工具调用时间线、审批按钮）；Docker Compose 部署；公开 demo 怎么防止被刷 API 费用。

**验收**：一条命令启动全部服务；公开 demo 可以访问；README 附架构图和演示视频脚本。

**面试常问**：SSE 和 WebSocket 怎么选？工具调用的中间状态怎么推给前端？

## 5. 时间和预算

- **时间**：每周 10 小时以上，大致每周完成一个里程碑。M6 和 M7 内容多，各留 1.5–2 周。全部完成大约需要两个半月。
- **模型**：DeepSeek（OpenAI 兼容协议和 Anthropic 兼容协议都支持，一个 key 就能演示适配层的两种协议）。
- **预算**：每月 ¥50 以内。日常开发和评测都用 DeepSeek；embedding 用本地开源模型（DeepSeek 没有 embedding 接口），不花钱。从 M1 开始，每次调用都会记录 token 数和成本。
